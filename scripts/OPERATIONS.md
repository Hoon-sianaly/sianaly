## 평소 운영 순서

공개 초기 권장 점검 주기이며 예약 작업이나 알림을 생성한 것은 아님.

1. 매일: 문의 메일, 마이페이지 → 오류 제보 관리의 미처리 목록 확인. 접수 → 검토 중 → 해결/반영 안 함으로 처리하고 공식 자료 링크와 수정 사유 기록.
2. 매일: 게시판 확인. 개인정보 노출·도배 등은 우선 숨김, 검토 후 복원 또는 삭제. 영구 삭제는 댓글도 함께 없어지므로 복원 가능한 숨김을 먼저 사용.
3. 매일: GitHub Actions → DART disclosure updates의 최근 성공 시각·요약·검토 대기 항목 확인. 한국 시간 03:17·09:17·15:17·21:17 예정이며 지연 가능. 새 공시가 없으면 데이터 변경이 없어도 정상.
4. 업데이트가 있다면 GitHub 저장 완료와 Cloudflare Pages 배포 성공을 따로 확인. 수정 대상 기업의 실제 JSON/화면까지 맞아야 반영 완료로 기록.
5. 매주 및 공개 직후: Cloudflare 요청/D1 사용량, Supabase 용량·인증 오류, Resend 발송량·실패·반송 확인. 도메인 갱신 시기와 서비스 계정 복구 수단도 확인.

## 저장소와 백업

| 저장소 | 내용 | 복구 준비 |

| Supabase | 회원 인증·별명·즐겨찾기·탈퇴 동기화 큐 | 무료 플랜의 정기 자동 백업을 전제로 삼지 않음. 공식 CLI 기반 비공개 내보내기와 별도 환경 복원 검증 필요 |
| Cloudflare D1 POPULAR_DB | 게시글·댓글·숨김·추천·조회·오류 제보·집계·요청 제한 | 실제 계정의 Time Travel 가능 시점 확인. 공식 한도는 Free 7일, Paid 30일. 별도 비공개 내보내기도 검토 |
| 외부 서비스 설정 | DNS·발신 도메인·CAPTCHA·인증 URL·서버 비밀 설정 | 설정 이름·용도·대상 환경 기록. 키 값은 공개 코드·문서·스크린샷에 보관하지 않음 |

백업은 개인정보를 포함할 수 있으므로 공개 저장소·Pages 업로드 디렉터리·공개 CI 산출물에 저장하지 않음. 로컬 임시 검증이 필요하면 Git/배포 제외된 tmp 아래에서만 진행하고, 장기 보관은 접근 제한·암호화된 별도 위치를 정한 뒤 진행.

복원은 기존 DB에 바로 덮어쓰지 않고 별도 환경에서 먼저 검증. 특히 Supabase의 탈퇴 큐와 D1의 탈퇴 익명화 처리가 서로 다른 시점으로 복원되면 탈퇴 회원 정보가 되살아날 수 있으므로 함께 대조. 백업의 삭제 요청 재적용·보관기간 정책도 회원 안내와 일치시켜야 함.

코드 롤백은 DB 롤백과 다름. 이전 버전이 현재 스키마·인증 설정과 호환되는지 확인한 뒤 실행. 복구 도중 탈퇴 처리·권한 검증을 우회하지 않음.

## 사용량과 비용

2026-11-07 공식 문서 기준이며 실제 계정 요금제·청구 내역을 새로 확인한 기록은 아님. 유료 전환은 아직 하지 않음.

- Resend Free: 월 3,000통·일 100통. 인증·재발송·비밀번호 찾기 메일이 발송량을 공유하므로 회원 수와 동일하지 않음. 초기에 일일 한도를 특히 확인.
- D1 Workers Free: 하루 읽기 500만 행·쓰기 10만 행, 계정 저장 5GB, 개별 DB 최대 500MB. 조회 요청 수와 읽기 행 수는 다름.
- Supabase: 기존 기록상 Free. 공개 전 현재 요금제·용량·백업 지원을 대시보드에서 확인. 비용을 정액 0원으로 확약하지 않음.
- 사용량이 포함량의 약 70%에 이르거나 증가 추세가 급하면 점검하는 운영 기준을 제안. 자동 경보를 설정한 상태는 아님.
- 실제 월 예산 상한, 유료 전환 기준은 사용자 결정 후 기록. 로고·상표 등록은 별도 후속 작업.

## 실제 사이트 이전 순서

1. 실제 도메인의 Pages 프로젝트·배포 브랜치·DB 공유/분리 정책 결정. 개발 회원/게시글을 가져갈지 먼저 정함.
2. 필요한 서버 설정·D1 바인딩을 대상 프로젝트에 연결하고, 인증 Site URL/정확한 redirect URL·메일 링크·Turnstile 허용 도메인 반영.
3. 공개 도메인에서 가입·메일 인증·로그인 유지·복구·권한·탈퇴 익명화·제보·추천/조회 확인. dev 설정을 복사하는 것만으로 완료 처리하지 않음.
4. 최신 기업 데이터·업데이트 대상 도메인·실제 배포 검증을 함께 전환. 현재 DART 자동 갱신의 배포 확인 대상은 dev 사이트.
5. 안내문·검색 노출·문의 경로 확인 후 공개. 현재 문서 작성만으로 실제 도메인 전환이나 외부 공지는 하지 않음.

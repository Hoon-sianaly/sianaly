# 인기 기업

홈 검색창 아래 중앙형 TOP 5. 최근 24시간에 실제로 열린 기업 페이지의 익명 조회수를 기준으로 하며, 순방문자 수는 아님. 순위는 5분 캐시 및 화면 갱신 주기를 사용함. 순위가 없는 기간이나 API 장애 때에는 예시 기업을 끼워 넣지 않음.

## 연결

- 기존 dev.sianaly.com을 서비스하는 Cloudflare Pages 프로젝트에 D1 데이터베이스 `sianaly-popular`를 생성·연결. 바인딩 이름은 `POPULAR_DB`.
- 기존 sianaly.com 프로젝트와는 별도 연결. 현재 작업 대상은 개발 사이트임.
- 첫 API 호출에서 `popular_views` 테이블과 시간 인덱스를 자동 생성. 기존 테이블을 삭제하거나 변경하지 않음.
- `/api/popular` GET은 순위 조회, POST는 기업 페이지 조회 기록. `_routes.json`은 해당 API에만 Functions를 실행하고 기존 정적 페이지 경로를 유지함.
- 바인딩을 변경한 뒤에는 해당 Pages 프로젝트에서 최신 main을 다시 배포해야 적용됨.

## 데이터와 중복 처리

저장하는 필드는 조회 이벤트의 무작위 UUID, 기업 키, 서버 시각뿐. 이름·이메일·계정·IP·사용자 에이전트를 저장하지 않음. 사용자 식별 쿠키를 생성하지 않으며 조회 요청에 쿠키를 첨부하지 않음. 기록은 순위 조회 시 48시간을 넘은 항목부터 제거함.

정상적으로 로딩된 기업 페이지가 화면에 나타난 뒤 기록. 같은 탭 세션에서 같은 기업은 30분에 한 번만 집계하고, 요청 재시도는 같은 이벤트 ID를 사용해 서버에서 중복 제거. 저장 기능을 차단한 브라우저나 새 탭까지 동일인으로 추적하지 않음. 알려진 크롤러는 제외하지만 방문자 신원을 판별하는 부정 집계 방지 시스템은 아님.

기업 키는 배포에 포함된 회사 목록으로 검증. 외부 Origin의 POST, 잘못된 이벤트 ID, 추가 개인 정보 필드, 큰 요청 본문은 거절. 순위 API 쿼리 문자열로 5분 캐시를 우회하지 않음.

## 검증

`node scripts/test-popular.cjs` — 실제 SQLite 쿼리, 24시간 범위, 48시간 삭제, 중복 ID, 동일 출처·기업 검증, 캐시, 화면의 기업명·링크·빈 상태, 30분 클라이언트 재집계 방지와 동일 ID 재시도.

`npx wrangler@4 pages functions build . --outdir tmp/popular-functions-build` — Pages Function 컴파일.

`npx wrangler@4 pages dev . --d1 POPULAR_DB --persist-to tmp/popular-local-state` — 실제 서비스와 분리된 로컬 D1 검증. 로컬 테스트 조회는 공개 순위에 전달되지 않음.
